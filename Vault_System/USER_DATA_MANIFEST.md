# POPS Vault User Data Manifest

This folder describes the product-owned safety boundary for POPS runtime data.

Runtime root:

```text
C:\Users\bryan\Desktop\POPS_Application\Vault_System\
```

This build treats the application-owned `Vault_System` folder as the product data boundary. Tauri resolves the Vault root in this order:

```text
1. POPS_VAULT_SYSTEM_DIR, when explicitly set
2. Vault_System beside the running application or project root
3. Tauri app_data_dir / Vault_System only as a fallback
```

Owned runtime locations:

- `database/proof_of_presence.db` - SQLite source of truth for evidence, events, incidents, reports, profile, sealed records, audit ledger, case calendar scaffolding, communication imports, and contact research.
- `evidence_originals/` - preserved imported evidence files, keyed by evidence ID.
- `communication_exports/` - preserved message or communication exports and screenshots.
- `dossiers/contacts/<dossier_uuid>/` - person/contact dossier snapshots keyed only by stable UUID. Each dossier gets `current.json`, `history/`, `documents/`, `notes/`, and `research/`. Names, phone numbers, emails, addresses, and private notes must not be used in filesystem paths, telemetry, glyph traces, diagnostics, or generic analytics.
- `child_support_ledger/<record_uuid>/` - child-support payment ledger snapshots, history, receipt/statement hashes, corrections, disputes, missed-payment claims, certified-record flags, and delete tombstones. SQLite remains the current-state source of truth; these folders are the auditable history layer.
- `browser_records/` - audited safety mirror for frontend-only operational records such as Case Calendar entries. Browser storage may still act as UI cache, but each save/delete is written here and chained into `audit_ledger`.
- `case_bundles/` - full case bundle exports generated by the app.
- `exports/` - database and document exports.
- `runtime_cache/` - disposable runtime cache.
- `derived_state_cache/` - disposable rebuilt/derived state.
- `temp_exports/` - disposable temporary export files.

SQLite remains the authoritative live record. Dossier files are an auditable mirror/history layer only. Every dossier save/delete and mirrored browser record writes UUID, action, UTC timestamp, actor/source, previous-record hash, new-record hash, snapshot path, and audit-chain entry hash. Deletes write tombstones; they do not erase dossier history or attachments.

The product backend creates these folders idempotently and migrates legacy Tauri app-data content into this runtime root when the vault copy is missing.
