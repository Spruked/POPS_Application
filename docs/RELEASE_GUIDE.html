POPS Mobile: Install & Release Guide

App: POPS (Proof of Presence)  |  Android package: com.proofofpresence.app
Repository: github.com/Spruked/POPS_Application  |  Branch: mobile-tauri-v2

Note: POPS is a Tauri app, so it does not run in the Emergent preview window or in Expo Go. To try it you install the Android file (APK) built by GitHub Actions, as described in Part 1.

Part 1: Install POPS on your Android phone (about 5 minutes)

  1. Go to github.com/Spruked/POPS_Application and sign in.
  2. Open the Actions tab and click the latest run with a green check on branch mobile-tauri-v2.
  3. Scroll to the bottom to Artifacts and download pops-android. You get a .zip file.
  4. Unzip it and find apk/universal/debug/app-universal-debug.apk.
  5. Copy the APK to your phone. You can email it to yourself, upload it to Google Drive, or use a USB cable.
  6. Tap the APK on your phone. When Android asks, allow "Install unknown apps" for that app (Files, Gmail or Drive), then tap Install.
  7. Open POPS. Allow Camera and Location when it asks.

Part 3: First upload to Google Play (one time, by hand)

Google requires the first build to be uploaded by hand. After that, uploads can be automatic (Part 4).

  1. Open play.google.com/console → Create app. Name: POPS. Choose App, Free, and accept the declarations.
  2. In the left menu go to Test and release → Testing → Internal testing → Create new release.
  3. Upload bundle/universalRelease/app-universal-release.aab from the same pops-android zip from Part 1.
  4. Make sure the package name shows com.proofofpresence.app. Save the release and roll it out to internal testing.
  5. Open the Testers tab, create an email list, add your Gmail, and save. Then open the opt-in link on your phone to install from Play.
  6. Fill in App content, including the privacy policy URL: https://www.popsproof.com/privacy (the page is in store/privacy.html).

Part 4: Turn on automatic Play uploads from GitHub

Step A: Create a service account key in Google Cloud

  1. Open console.cloud.google.com and select (or create) a project.
  2. Go to APIs & Services → Library, search for Google Play Android Developer API, and click Enable.
  3. Go to IAM & Admin → Service Accounts → Create service account. Name it pops-ci, then click Done.
  4. Open the new account → Keys → Add key → Create new key → JSON. A .json file downloads. Keep it private.
  5. Copy the service account email (it looks like pops-ci@your-project.iam.gserviceaccount.com).

Step B: Give that account access in Play Console

  1. Play Console → Users and permissions → Invite new users.
  2. Paste the service account email. Under App permissions, add POPS and tick Release apps to testing tracks and Manage testing tracks (or choose Admin).
  3. Click Invite user. Access can take a few minutes, and sometimes up to 24 hours, to start working.

Step C: Add the secret to GitHub

  1. GitHub repo → Settings → Secrets and variables → Actions → New repository secret.
  2. Name: PLAY_SERVICE_ACCOUNT_JSON (exactly this). Value: open the .json file in a text editor and paste the whole contents, including the { } brackets.
  3. Optional: on the Variables tab, add PLAY_RELEASE_STATUS = completed once Google has approved the app. Until then, uploads arrive as drafts.
  4. Push any change to mobile-tauri-v2, or re-run the workflow. In Actions, the step "Upload to Google Play internal testing" should now run instead of showing "skipped".

Part 5: iOS signed builds (when you are ready)

You need an Apple Developer Program membership ($99/year). Add these GitHub secrets the same way as in Step C:
