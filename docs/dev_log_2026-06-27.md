## Product Decisions Confirmed

- P.O.P.S. remains the application name.
- **Pops!** is the in-app assistant name.
- Pops! must feel like a private guide inside the desktop workspace, not a generic chat bubble, developer console, case-worker relationship, or separate ungoverned chatbot.
- POPS is local-first. Tauri/Rust/SQLite remains the durable record authority.
- A future LLM may improve conversation and articulation, but it is not the final authority for facts, permissions, case direction, or durable writes.

## Important Current Limits

1. **Pops! is not yet connected to TPC cognition or an ANSKG package.**
   - The current Core Guided Mode behavior is a temporary frontend placeholder.
   - It is not the final TPC-governed assistant controller.

2. **Contact research is a starter workspace, not an integrated search-provider system.**
   - The current buttons open user-started external searches.
   - No search API provider is configured.
   - No external credentials are stored.
   - No automatic enrichment or background search exists.

3. **Research findings are not yet a dedicated research table.**
   - They are temporarily represented inside the existing contact interaction history.
   - A dedicated data model, links to evidence/events/orders, durable receipts, and review flow are still required.

4. **No new durable action should be reported as complete until the native Tauri/SQLite layer returns a receipt.**

## Required Next Architecture

```text
Pops! UI
-> POPS assistant controller
-> TPC governance and policy route
-> POPS ANSKG / lexicon / navigation package
-> approved local data or search-provider adapter
-> reviewed draft or pending finding
-> user confirmation when required
-> Tauri / SQLite durable write
-> receipt
-> governed user-facing response
```

For contact research:

```text
Contact dossier
-> research question
-> user-selected provider or API adapter
-> returned results for review
-> user chooses what to preserve
-> structured research finding
-> optional links to evidence, event, order, or timeline record
-> local durable receipt
```

## Codex Guardrails for the Next Pass

- Do not replace the existing Tauri/SQLite contact storage with browser-only storage or a second database.
- Do not rewrite or delete the Pops! dock, Contacts Dossier, or existing dossier fields unless required for a verified build fix.
- Do not treat the current UI placeholder as proof of TPC integration.
- Do not send private case material to a provider without an explicit user-controlled configuration and approved context boundary.
- Preserve the distinction between source-backed information, user-provided information, second-hand information, and items that still need verification.
- Build and run the Tauri app after changes; report exact errors rather than claiming success without evidence.
